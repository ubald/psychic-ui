# Review 2026-11: checklist

The findings of the November 2026 review of `revival-2026` (at `94099c1`, seven read-only reviewers), as a
checklist. The readable snapshot, with the reasoning behind each finding, is the review page (private):
https://claude.ai/artifact/9PNMDfxhEkGMvwBPfbH3t1. File and line references are as of `94099c1`.

Each item has a stable id. Tick it in the commit that fixes it, and in that commit:

- **`[!shouldfail]` tests** encode the correct behaviour of a reproduced bug. Catch2 reports them as expected
  failures, so the suite stays green; once the bug is fixed the test passes, which Catch2 reports as a failure,
  until the tag is removed. Every one of them is named after its item (`C2: ...`).
- **`[asan]` tests** (`tests/asan/use_after_free_tests.cpp`) are hidden (`[.]`): use-after-free and crash paths that
  only show under AddressSanitizer, and that would kill the whole run without it. See [Running the asan tests](#running-the-asan-tests).
  Each one aborts today; when its item is fixed it passes, and can move to the default run.

Severity: critical, high, medium, low. Evidence: *reproduced* (a test or a sanitizer showed it), *checked* (read in
the source), *reasoned* (traced, not run).

Tests that exist for an item are listed after it. Items without one either can't be tested as a unit (toolchain,
organization) or were only checked or reasoned; writing the test is part of fixing them.

## Memory

Keyboard dispatch and the focus path are the common cause of M1 to M4: mouse dispatch keeps each div alive with a
`keepAlive` while its handlers run; `Window::handleKeyPress`, `handleKeyRepeat`, `handleKeyRelease`, `handleType`
and the keyboard context menu emit on raw `Div *` from `_focusPath`. Fix: hold `shared_from_this()` around each emit,
make `_focusPath` a list of `weak_ptr`, and in `requestFocus` assign the new path before emitting anything, stopping
if a nested call changed it.

- [ ] **M1** critical, reproduced. A blur handler that removes the div being focused leaves it in the focus path
  (`Window.cpp:962-1010`, the crash at `:1347`): the press's `keepAlive` ends and the next key reads freed memory.
  - `[asan]` M1: a blur handler detaches the div the press focuses
- [ ] **M2** critical, reproduced. `requestFocus` from a focus handler (`Window.cpp:996-1010`): from `focused` it frees
  the vector being iterated; from an ancestor's `blurred` it recurses until the stack overflows.
  - `[asan]` M2: a focused handler on an ancestor redirects the focus
  - `[asan]` M2: a blurred handler on an ancestor moves the focus
- [ ] **M3** high, reproduced. Components freed by their own change handler during a key touch themselves after the
  emit (`Range.hpp:269`, `ColorSwatches.cpp:138`, `Text.cpp:104`, `Rows.cpp:292`). Legal by the event conventions,
  and it works from the mouse.
  - `[asan]` M3: range removes itself on change
  - `[asan]` M3: color swatches remove themselves on change
  - `[asan]` M3: text input removes itself on change while typing
  - `[asan]` M3: list removes itself on selection change (keys)
- [ ] **M4** high, reproduced. Rows used after `selectionChanged` or `clicked` (`Rows.cpp:283-295`, `Rows.cpp:22-26`,
  `Sidebar.cpp:142`, `Tree.cpp:263`): the freed object is the row, not the emitter, so a `keepAlive` on the group isn't
  enough. Take `row->shared_from_this()` at the start of `moveTo`, `handleRowKey` and the row's click lambda.
  - `[asan]` M4: delete rows during selectionChanged
  - `[asan]` M4: clear all rows during selectionChanged, then keys
  - `[asan]` M4: tree removes the selected node on selection change (keys)
  - `[asan]` M4: sidebar removes the item on change (keys)
- [ ] **M5** high, reproduced. A check menu item's callback is freed while it runs (`Menu.cpp:213-214`): closing the
  menu from the callback destroys the executing `std::function`. `finish()` already copies the callback for simple
  items; do the same in the check branch.
  - `[asan]` M5: a check item's callback closes the menu
- [ ] **M6** high, reproduced. A child that outlives its parent keeps a dangling `_parent` (`Div.cpp:56`); parts are
  handed out as `shared_ptr` (`SearchField::input()`, `TextInput::textDisplay()`), so they outlive their skin, and
  their signals capture the owner's `this`. Fix with M12 (clear each child's `_parent` in `~Div`) and by not
  handing parts out as owners.
  - `[asan]` M6: a child outlives its parent
  - `[asan]` M6: a SearchField's input outlives the field
- [ ] **M7** high, reproduced. `add(child)` doesn't detach the child from its old parent (`Div.cpp:163-175`):
  `p1.add(c); p2.add(c);` puts `c` in `p2`'s children list, then Yoga throws ("Child already has a owner"), leaving
  `c` in both lists with `_parent` still `p1`. `insertChild` should detach first, as `Overlay::open` does.
  - `[!shouldfail]` M7: adding a child that has a parent moves it
- [ ] **M8** medium, reproduced. A row moved to another tree stays the old tree's selection (`Rows.cpp:177`,
  `Tree.cpp:238`): `removed()` fires only on the root of a removed subtree, so a `TreeNode`'s row never tells its group;
  the old tree then reaches the row after it is freed.
  - `[!shouldfail]` M8: a selected tree node moved to another tree stops being the first tree's selection
  - `[asan]` M8: a selected row moved to another tree, then freed
- [ ] **M9** medium, reproduced. `Tabs` dereferences null on its first render and captures a dangling reference
  (`Tabs.hpp:54`, `:94`). Nothing uses it: delete it (see O3), or fix and test it.
  - `[asan]` M9: a TabContainer renders before anything is selected
- [ ] **M10** medium, reasoned. Backend lifetimes:
  - the SDL hit-test callback isn't cleared in the adapter's destructor (`SDL3SystemWindow.cpp:169`);
  - the GLFW trampolines call into the adapter after the host's callback, which may have destroyed it;
  - `SDL3Application::close` from a handler frees the adapter whose `handleEvent` is running;
  - when a window moves to another system window, the old `GrDirectContext` is freed while the new GL context is
    current.
- [ ] **M11** low, reasoned. Smaller undefined behaviour:
  - the fling velocity has no cap, so the cast of its step to `int` can overflow (`Window.cpp:816`);
  - `::tolower` on negative chars for non-ASCII selectors (`StyleManager.cpp:164`);
  - `reloadRules` iterates `_styleSheets` while `load()` can append to it;
  - children are iterated by reference while `styleUpdated` and `resized` run user code;
  - `TextLayout`'s implicit move leaves the ICU iterators pointing at the source;
  - drag areas are duplicated each time a title bar is re-added;
  - `fontFamily(p)` with a null `const char *` builds a `string_view` from null.
- [ ] **M12** medium, checked. `~Div()` isn't virtual, in `Div` nor `Observer`: safe only because everything goes
  through `make_shared<Concrete>`. Make it virtual, and clear each child's `_parent` in it (M6).
  - `[!shouldfail]` M12: Div has a virtual destructor
- [ ] **M13** Write down the lifetime rules the code relies on (the review's list), in CLAUDE.md or the headers, and
  drop each one a fix makes unnecessary:
  - divs must be owned by a `shared_ptr` (`keepAlive`, popup anchors, drag areas, `ScrollBar` and `Overlay::close`
    depend on it);
  - code after an emit must not touch `this` on keyboard paths (M1 to M4 remove this one);
  - a child must be removed before it is added elsewhere, and must not outlive its parent (M6, M7);
  - `added()` and `removed()` fire only on the root of a moved subtree, the render hooks recursively (M8);
  - `styleUpdated`, `resized`, `layoutUpdated` and `render` must not change their parent's children;
  - `StyleSheet::load` must not load other stylesheets;
  - a `Window` must be released in the GL context that created its Skia context;
  - everything is single-threaded: the `Atom` table, `StyleManager::getInstance`, `IconRegistry::shared`, the Yoga
    config.

## Correctness

- [ ] **C1** critical, reproduced. A focused component swallows every key: the key goes to the deepest `keyPressed`
  subscriber and stops, so after a click on a button, app shortcuts like Ctrl+S never reach the app. Key handlers
  should say whether they used the key (a return value or `event.handled`), and the key bubble up the focus path
  until one does.
  - `[!shouldfail]` C1: a key a focused Button doesn't use reaches the app's shortcut
  - `[!shouldfail]` C1: a key a focused list row doesn't use reaches the app's shortcut
- [ ] **C2** high, reproduced. Text editing breaks on emoji and on select-all. `Text.cpp:209` advances the caret by
  one UTF-16 unit after typing, and Backspace, Delete and the arrows step one unit; Ctrl+A then Delete (caret at the
  end) or Backspace (caret at the start) does nothing, since lines 348-387 check the caret before the selection.
  Advance by the inserted length, step with ICU character breaks, check for a selection first.
  - `[!shouldfail]` C2: typing a character outside the BMP puts the caret after it
  - `[!shouldfail]` C2: Backspace removes a whole character outside the BMP
  - `[!shouldfail]` C2: Left steps over a whole character outside the BMP
  - `[!shouldfail]` C2: select all then Delete with the caret at the end empties the field
  - `[!shouldfail]` C2: select all then Backspace with the caret at the start empties the field
- [ ] **C3** high, reproduced. A div hidden or removed mid-press stays pressed: `Div::handleMouseRelease` returns
  early when hidden (`Div.cpp:1452`), a removed div never hears the release, drags never end, it shows `:active`
  when shown again, and a later press on a sibling released over it clicks it. The pressed flag is also one for
  every button, so a second button's release ends the first's press. Record the pressed path per button (weak
  pointers taken at the press) and send the release to it.
  - `[!shouldfail]` C3: a div hidden mid-press hears the release and stops being pressed
  - `[!shouldfail]` C3: releasing a second button keeps the first button's press
- [ ] **C4** medium, reproduced. `DataGrid` sort reads words as numbers (`DataGrid.cpp:20`, `strtod`): "Nancy" is NaN,
  "Info.txt" infinity, and NaN makes the comparator inconsistent (undefined behaviour in `stable_sort`); it also
  follows the locale and accepts hexadecimal. Use `std::from_chars` after checking for a leading digit or sign, and
  compare non-finite values as text.
  - `[!shouldfail]` C4: DataGrid sorts words that start like nan or inf as text
- [ ] **C5** medium, reproduced. The scroll offset isn't corrected when the content shrinks (`Div.cpp` ~1711): a
  filtered list can sit off-screen with the wheel dead.
  - `[!shouldfail]` C5: the scroll offset follows content that shrinks
- [ ] **C6** medium, reproduced. A wheel notch moves 2 px (`ceil(delta) * 2`, `Div.cpp` ~1741), and fractional
  deltas are asymmetric (down by half a notch doesn't move, up does). Decided (Ubald, 2026-11-14): a fixed number
  of pixels per notch, about 48 (three 16 px lines), with fractional deltas accumulated so trackpads scroll smoothly
  and both ways alike; no theme value and no system setting for now. Tighten the notch test to the chosen value.
  - `[!shouldfail]` C6: fractional wheel deltas scroll both ways alike
  - `[!shouldfail]` C6: a wheel notch scrolls more than 2 px
- [ ] **C7** medium, reproduced. Nested scrollers both scroll on one wheel event (`Div.cpp:1781`).
  - `[!shouldfail]` C7: a wheel event scrolls the innermost scroller only
- [ ] **C8** medium, reproduced. Removing the list row that holds the Tab stop makes the list unreachable by Tab
  (`Rows.cpp`, `forget`).
  - `[!shouldfail]` C8: removing the row that holds the list's Tab stop leaves the list reachable by Tab
- [ ] **C9** medium, reproduced. Under a modal popup, the div under the pointer keeps `:hover` and keeps getting
  `mouseMoved`. (No tooltip shows there, which a regression test now holds: "No tooltip shows for a div under a
  modal dialog".)
  - `[!shouldfail]` C9: under a modal dialog, the div under the mouse loses its hover and its moves
- [ ] **C10** medium, reproduced. A touch cancel swallows the next release when the cancelled press had closed a
  modal (`Window.cpp` ~922): `_pressSwallowed` is never cleared.
  - `[!shouldfail]` C10: after a touch cancel whose press closed a menu, the next click goes through
- [ ] **C11** medium, reproduced. `focused` fires again for the whole path on every press inside a focused div: a
  "select all on focus" handler would undo every click.
  - `[!shouldfail]` C11: presses inside a focused field don't focus it again
- [ ] **C12** medium, reasoned. Neither backend reports the pointer leaving the window: hover stays on, and a tooltip
  appears 300 ms after the pointer has left.
- [ ] **C13** low, reproduced. `NumberStepper` with `decimals(0)`: typing 1.75 stores 1.75 while the field shows 2.
  - `[!shouldfail]` C13: NumberStepper keeps the value it shows, rounded to its decimals
- [ ] **C14** low, reproduced. `NumberStepper` with `step(0.5).decimals(0)`: stepping down from 1 is stuck.
  - `[!shouldfail]` C14: NumberStepper steps down with a step finer than its decimals
- [ ] **C15** low, reproduced. A popup that closes gives the focus back to a trigger that has since been disabled or
  hidden.
  - `[!shouldfail]` C15: a menu closing doesn't give the focus back to a trigger disabled meanwhile
- [ ] **C16** low, reproduced. An integer `Range`: a small downward wheel scroll can't move it. Every `Range` also
  takes the wheel, so a page scrolling past a slider changes the slider's value.
- [ ] **C17** low, reasoned. The horizontal wheel on SDL3 is probably inverted.
- [ ] **C18** low, reasoned. Smaller:
  - key repeat: lists and menus ignore it, and so does Tab;
  - a single-line `TextInput` never scrolls to its caret, and `TextArea` prints debug output on every caret move;
  - Ctrl+click on macOS: its state isn't reset by a plain left press;
  - layout rounding: `layoutUpdated` rounds `_x` and `_width` up separately, so siblings overlap by 1 px;
  - `Range<double>` goes through `float`;
  - several windows: a density or theme switch drops the other windows' runtime rules;
  - hit slop can reach content under popups.

## Style

CLAUDE.md says the cascade follows CSS and that an unparsable selector throws; neither holds yet. Weigh selectors as
the tuple (ids, classes and pseudo-classes, tags), throw on unknown pseudo-classes and combinators, and handle every
`Pseudo` value.

- [ ] **S1** high, reproduced. `StyleSelector::weight()` adds 15 per id and 10 per tag and class, so `.a .b` beats
  `#x`; pseudo-classes weigh 1 to 4 each, so `:disabled` always beats `:hover` whatever their order, and `.a:hover`
  loses to `div .a`.
  - `[!shouldfail]` S1: an id outweighs any number of classes, as in CSS
  - `[!shouldfail]` S1: a pseudo-class weighs as much as a class, more than a tag
  - `[!shouldfail]` S1: pseudo-classes weigh the same, so the one declared last wins
- [ ] **S2** high, reproduced. `:focus-visible` is missing from `weight()`'s switch and weighs 0 (also one of the five
  library warnings, B7).
  - `[!shouldfail]` S2: :focus-visible weighs like any pseudo-class
- [ ] **S3** high, reproduced. An unknown pseudo-class (`:checked`, `:focus-within`) is silently dropped, so the rule
  matches everything its selector without it matches. Decided (Ubald, 2026-11-14): support the useful one,
  `:focus-within` (restyling the focus path's ancestors when the focus moves), and throw `std::invalid_argument` for
  every pseudo-class still unknown; `:checked` stays unsupported, since the `checked` class already says it.
  - `[!shouldfail]` S3: an unknown pseudo-class is an invalid selector
  - `[!shouldfail]` S3: :focus-within matches while a descendant has the focus
- [ ] **S4** high, reproduced. `a>b` and `a, b` parse as nonsense (tags `a>b`, `a,`) instead of throwing.
  - `[!shouldfail]` S4: combinators and selector lists that aren't supported are invalid selectors
- [ ] **S5** low, reproduced. `:empty` isn't re-evaluated when the first child is added or the last removed.
  - `[!shouldfail]` S5: :empty stops matching once a child is added

## Performance

Measured on a headless debug build with a replaced `operator new`: allocation counts are reliable, times only
comparable with each other.

- [ ] **P1** high. The dot grid costs about 2,800 allocations and 10 ms per raster frame (`Div.cpp:1082-1112`; the
  Canvas page makes 3,577 allocations per steady frame, other pages 140 to 440), since the raster backend makes one
  shape per dot. One shader built in `styleUpdated` that fills the rect; also cache the shadow's blur filter
  (`Div.cpp:1063`), rebuilt each frame. CLAUDE.md's "only the visible dots, in one drawPoints" is misleading.
- [ ] **P2** medium. Hover, press and class changes restyle the whole subtree (`Div.cpp:439-451`, `1313-1329`): on the
  Lists page (655 divs) a mouse move costs 319 µs against 2.4 µs for the move alone. Record which pseudo-classes
  appear in non-rightmost selector parts, and invalidate only the div itself when none do.
- [ ] **P3** medium. Event dispatch copies the children list at every level (`Div.cpp:238`): 12 to 15 allocations per
  mouse move. Iterate by index from the end, holding only the current child.
- [ ] **P4** low. Smaller costs:
  - `window()` and `styleManager()` walk to the root on every call (55 call sites, hit testing and selector matching
    among them): cache a `Window *` in `addedToRender`;
  - styles are computed twice for new divs, eagerly in `setParent` and again in the frame;
  - header weight: `Div.hpp` preprocesses to 143k lines (ICU, `<iostream>`, `StyleManager` with skparagraph and the
    themes); `Window.hpp` includes `Menu.hpp`;
  - the SDL3 loop redraws every window every frame;
  - rule lookups hash a `std::string` per class, icon lookups build one; a `Style` is 528 bytes and every Div holds
    three.

## C++ design

Keep: the X-macro property table, the deducing-this chainable API, the value types (constexpr themes, typed `Length`,
`Color`, `Atom`), `Signal`/`Slot` (reentrancy-safe), shared ownership of the tree.

- [ ] **D1** Add `[[nodiscard]]` to the zero-argument getters: `button.enabled();` meant as a setter compiles and
  does nothing.
- [ ] **D2** Exclude character types from the number argument wrapper and reject null in the string wrapper:
  `width('x')` (120 px), `rgb(-1)`, `width(1e40)` and a null `const char *` all compile today.
- [ ] **D3** Give `lineHeight` a unit meaning "times the font size" (CSS's unitless value): today 1.5 means 1.5 px.
- [ ] **D4** Finish the rename to bare names: `Window` and `SystemWindow` still use get/set (and return `void`, as
  `SelectableRow::setSelected` does), and `setResizable` and `setDecorated` do nothing.
- [ ] **D5** `Component::skin()` returns `T *`, not a `shared_ptr` by value; `Slot::Callback` could be
  `std::move_only_function`.
- [ ] **D6** Remove from the public interface the `WIN`, `APPLE` and `UNIX` definitions exported to consumers, and
  the `DEBUG_LAYOUT` and `SYSTEM_COMMAND_MOD` macros (the latter names a GLFW constant) in `psychic-ui.hpp`.

## Toolchain

- [ ] **B1** high, checked. The shared build links Skia twice: the static Skia archives are linked PUBLIC into a
  library that is SHARED by default, so `libpsychic-ui.so` and each executable both contain Skia, with two glyph and
  resource caches (an ODR violation that works by luck); the `.so` also exports 225 Yoga symbols. Make static the
  default; if shared stays, hidden visibility, an export header and `--exclude-libs,ALL`.
- [ ] **B2** high, checked. Skia never rebuilds after a change (`extlib/skia/CMakeLists.txt:103-107` runs its build
  only when a `.a` is missing): a gn arg, the compiler or the Skia commit changes and the old libraries stay, under
  new defines. `bin/fetch-gn` also ran every time, needed the network and downloaded an unverified binary (fixed: CMake downloads gn once, against a SHA-256). A custom
  target that always runs ninja (about a second when nothing changed), and `find_program(gn)` as for ninja.
- [ ] **B3** medium, checked. The README sends newcomers the wrong way: says the project is paused, skips
  `git submodule update`, uses a non-preset `mkdir build`, never says GCC 14 or newer is needed. Replace the build
  section with the three preset commands and the compiler note.
- [x] **B4** medium. The library can't be consumed cleanly: no install or export rules (no `find_package`); under
  `add_subdirectory` it builds its tests, demo and playground and forces `BUILD_SHARED_LIBS` on the parent; no
  `psychic-ui::psychic-ui` alias; CPack packages an empty archive. Default the build options to
  `${PROJECT_IS_TOP_LEVEL}` (psychic-color already does), add the alias, delete CPack.
- [ ] **B5** medium. About 60 lines of dead configuration: ~~GLAD (on WIN32 it would fetch an unpinned master),
  `PSYCHIC_UI_WITH_GLAD`~~ (removed), ~~ExternalProject~~ (removed), rxcpp, `LIBPSYCHIC_UI_EXTRA_SOURCE`, the version and package variables,
  `@SWITCHER_VERSION_MAJOR@` in `Doxyfile.in`.
- [ ] **B6** medium. The Catch2 check (`try_compile` sub-project and cache logic) is more machinery than it's worth,
  and the download is by git tag with no hash: always download it by URL with a SHA-256, as SDL3 and GLFW are.
- [ ] **B7** medium. CI runs twice per PR push (`ci.yml:3-6`: `push` on all branches and `pull_request`, no
  concurrency group), at the cost of free minutes; the Skia cache key ignores the compiler version.
- [ ] **B8** low. Smaller:
  - every non-Debug shared build is stripped after linking, RelWithDebInfo included;
  - ~~the compiler check advertises MSVC 17.2+, but nothing builds on Windows (`-Wextra`, Skia built by a bash script,
    `M_LOG10E` without its define)~~: Windows builds and runs its tests with clang-cl (the `windows` preset); no DLL
    exports, so shared builds are refused on Windows;
  - the Skia submodule is a full clone (1.1 GB of history), it could be shallow;
  - the flake is x86_64-linux only;
  - Yoga builds with `-Werror`, so a newer compiler can break the build in third-party code;
  - 5 library warnings under `-Wall -Wextra` (one is S2) and no CI gate: `COMPILE_WARNING_AS_ERROR` in CI;
  - `res/` is copied at configure time, so edits don't reach the build until a reconfigure;
  - `.idea/` is tracked.
- [ ] **B9** Stray directories, for Ubald to delete by hand: `extlib/external/depot_tools/` (12 MB, untracked, not
  ignored, referenced by nothing), the top-level `build/` (620 MB, the old non-preset build; only `build/debug` is
  used), `baseline/` (2018 screenshots, ignored only through a local `.git/info/exclude`; fine if deliberate).

`DefaultSkins.cpp`'s 99.8% means "it ran".

## Design risks

Not tracked as items, since none is a bug today, but each limits where the library can go: no accessibility; no
input-method composition (`SDL_EVENT_TEXT_EDITING` isn't handled); no undo, no Shift+arrow selection, right-to-left
selection drawn as one span; the HiDPI scale ignores the display scale on Windows and X11; every frame redrawn and
every window's swap blocking in turn; Windows built by hand only (no CI job).

## Running the asan tests

The `asan` preset builds a static debug library and the tests with AddressSanitizer and UndefinedBehaviorSanitizer
(no demo, no playground):

```sh
mkdir -p build/asan/extlib/skia && cp -a build/debug/extlib/skia/build build/asan/extlib/skia/  # skip Skia's build
cmake --preset asan
cmake --build --preset asan -j"$(nproc)" --target psychic-ui-tests
cd build/asan/tests
export LSAN_OPTIONS=suppressions=$PWD/../../../tests/asan/lsan.supp
./psychic-ui-tests                     # the default run: clean
./psychic-ui-tests "M1: a blur*"       # one [asan] test; each aborts on its first error, so run them one by one
./psychic-ui-tests --list-tests "[asan]"
```

Two things the preset handles, which anyone sanitizing this project otherwise trips on:

- `-fno-sanitize=vptr`: UBSan's vptr check needs RTTI, and Skia is built without it, so it doesn't link.
- Skia is built without ASan, but its headers give `TArray` an extra field when they see ASan, so our code and Skia
  disagree on the size of `TypefaceFontProvider` (96 bytes against 88) and ASan stops on a false
  new-delete-type-mismatch. `tests/asan/skasan_shim.h`, force-included (`-include`), keeps Skia's layout. A Skia built
  with ASan wouldn't need it.

And one about writing these tests: `make_shared` puts the object and its control block in one allocation, which stays
allocated while any `weak_ptr` lives, so ASan doesn't see reads of a destroyed div. The `[asan]` tests allocate what
should be freed with `shared_ptr<T>(new T)`. `tests/asan/lsan.supp` silences fontconfig's caches, the only leaks.
