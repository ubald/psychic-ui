◆ ctrlClickIsRightClick()

bool psychic_ui::Window::ctrlClickIsRightClick ( ) const
inline

Whether the right button asks for a context menu on its release, as on Windows (the default there), rather than on its press, as on macOS and Linux (the default elsewhere). A touch long press always asks on the press (it is held), the keyboard when its key goes down. Whether a left press with Control (and no other modifier) is a right press, for the whole press and its release (the right button, a context menu, no click), as Cocoa applications do on macOS (the default there; AppKit delivers it as a left press with Control, and SDL leaves it so by default). Not for touches.

◆ post()

void psychic_ui::Window::post ( std::function< void()> task)

Hand a task to the UI thread, from any thread: it runs at the start of the next frame (runPosted, first in drawAll), after the tasks posted before it, and asks for that frame (requestFrame). The UI stays single-threaded: another thread changes the window and its divs only through a task. A hidden window (windowVisible() false) runs its tasks once it draws again, so stop or coalesce posts to one. A task must not capture a shared_ptr to the window (the queue would keep it alive: a cycle); capture a weak_ptr, or a raw pointer whose lifetime the caller guarantees. Tasks still queued when the window is destroyed are destroyed without running; the caller must stop posting before that.
