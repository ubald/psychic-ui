Detailed Description

Shows a Psychic UI Window in a GLFW window that a host application owns. The host initializes GLFW, creates the window with an OpenGL 3.3+ context and runs the loop; the adapter only installs its input callbacks over the host's, chaining to them, and draws on request: 

GLFWwindow *glfwWindow = glfwCreateWindow(1280, 720, "Host", nullptr, nullptr);
glfwMakeContextCurrent(glfwWindow);
glfwSetKeyCallback(glfwWindow, hostKeyCallback);      // still called: the adapter chains to it

auto ui = std::make_shared<MyWindow>();
psychic_ui::GLFWSystemWindow adapter(ui, glfwWindow);

while (!glfwWindowShouldClose(glfwWindow)) {
    glfwPollEvents();
    adapter.render();                                   // makes the context current and draws
    glfwSwapBuffers(glfwWindow);
}

Install your own callbacks before creating the adapter: it calls the ones it replaces first, then handles the event. Destroy the adapter before the window: it puts those callbacks back.

Limits are GLFW's: no input method composition (characters arrive as typed), and on Wayland the window can't be moved from inside (supportsDrag() is false), so use system decorations there rather than a custom title bar. GLFW has no touch input either: the window stays in pointer mode, whatever the system makes of fingers, and the adapter never changes the mode, so a host with touch input of its own can hand it to Window::handleTouchPress and the others.
